# Contributing to MothaSync

I welcome your input, whether it is a bug report, documentation improvement, fix, feature proposal, or help maintaining the project.

## I develop with GitHub

GitHub hosts the code, issues, feature requests, and pull requests for MothaSync.

## I use CircleCI, so code changes happen through pull requests

Pull requests are the best way to propose changes to the codebase. I actively welcome them:

1. Fork the repository and create your branch from `main`.
2. Add or update tests when your change affects code.
3. Update the documentation when your change affects user behavior or APIs.
4. Run `dotnet test` and `dotnet build` locally.
5. Ensure the CircleCI checks pass.
6. Open the pull request with a clear description of the change.

## Contributions are released under the MIT License

By submitting a contribution, you agree that it will be released under the [MIT License](https://github.com/timo-reymann/MothaSync/blob/main/LICENSE), unless the contribution is separately identified as third-party material.

## Report bugs using GitHub issues

Use [GitHub issues](https://github.com/timo-reymann/MothaSync/issues) to report public bugs.

Good bug reports include:

- A short summary and relevant background.
- Specific steps to reproduce, including sample code or files where useful.
- What you expected to happen.
- What actually happened.
- Relevant logs, screenshots, environment details, or attempted workarounds.

## AI-generated contributions policy

AI-assisted contributions are welcome, provided that:

1. The human author understands the change and can explain how it works.
2. The human author takes responsibility for the intellectual property and submitted result.
3. AI assistance is disclosed through commit attribution or the pull request description.
4. The contribution meets the same quality standards as any other contribution.
